# Email paging and recent overview

The inbox displays fixed pages of 15 imported emails, ordered newest first. Newer and Older replace the visible page rather than appending an endless list. At the end of saved mail, Load older emails explicitly imports another bounded page from each connected mailbox. Gmail follows its page token across the inbox without the former 21-day cutoff; Outlook requests pages of 15 ordered by received time. Provider cursors are tied to the connected account, saved between visits, and checked again when a fetch completes. Checking for new email preserves progress through older mail. Provider failures leave existing emails and continuation state intact.

Recent email overview covers only the newest 15 imported emails, regardless of which inbox page is open. It groups messages into Check before acting, May need a reply, Worth a look, and Lower priority. Local suggestions use the message text, saved summaries, and current scam checks. Promotions can be lower priority, but an unchecked message, warning, appointment, account notice, transaction, or deadline is not automatically dismissed. The overview does not know whether a person has already replied outside LifeLink.

Importance is determined by ordered rules over the sender, meaningful subject, and current readable text. Empty subjects include provider placeholders such as `(no subject)` and reply/forward prefixes. Image filenames, image-only HTML without useful alt text, mobile signatures, and clearly quoted history do not count as a new action request. Subjectless image/file-only messages and short casual notes are lower priority when no stronger signal exists. Explicit questions, reply requests, health/account-service sender hints, concrete appointments, deadlines, and account actions take precedence. A saved sender match uses only the owner's exact Trusted-circle email addresses, never a display-name match, and is not proof of sender identity. Images and attachment contents are not inspected by this algorithm. The same rules determine row labels and overview groups; cloud AI may explain a category but cannot override it. The overview cache key includes the rule version.

Cloud summaries require an explicit consent checkbox and button press. Practice emails never go to cloud AI, including when sample emails remain in a live account. The existing cloud-reading limits apply. Model ids and quotes are checked against this batch, warnings cannot be lowered, and local reply requests cannot be dismissed. Missing, duplicate, or unsupported items fall back to the local suggestion. The screen discards a cloud result when the inbox snapshot changes. Failure leaves the local overview available and explains that the provider may already have received the text.

Verification covers fixed page sizes, equal timestamps, continuation after new older-mail imports, owner-only reads and checks, account changes during fetches, provider cursors, malformed responses, priority rules, opt-in cloud analysis, Practice isolation, and cloud fallback. Provider transport is tested with synthetic responses; live Gmail/Outlook paging and cloud summary quality still need a signed-in provider run. Browser QA requires a signed-in account.
